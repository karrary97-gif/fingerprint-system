# نظام البصمة — FPSystem.exe (دليل كامل)

ملف exe واحد: الواجهة + وسيط الأجهزة + مزامنة تلقائية كل 15 دقيقة + أيقونة بجوار الساعة. لا يحتاج بايثون. المفتاح مضمّن (app/fp_key.txt).
لا تغيير مطلوب في Apps Script.

## أولًا: رفع المشروع إلى GitHub
1. ادخل github.com وسجّل حسابًا (أو سجّل الدخول).
2. اضغط «+» أعلى اليمين ← New repository. الاسم مثلًا `fp-system`. اختر **Private** (مهم: المفتاح داخل الملفات). اضغط Create repository.
3. فك ضغط fp-system-project.zip على الكمبيوتر، وادخل المجلد `fp-system` (تأكد أنك ترى داخله: app، assets، gas، .github، FPSystem.spec، requirements.txt).
4. في صفحة المستودع اضغط «uploading an existing file».
5. اسحب **كل محتويات** مجلد fp-system (وليس المجلد نفسه) إلى الصفحة، وانتظر انتهاء الرفع، وتأكد أن مجلد `.github` ظهر ضمن القائمة.
6. اكتب رسالة مثل «first» واضغط **Commit changes**.

بديل بالأوامر (إن كان Git مثبتًا): داخل المجلد
```
git init
git add -A
git commit -m "first"
git branch -M main
git remote add origin https://github.com/USERNAME/fp-system.git
git push -u origin main
```

## ثانيًا: بناء الـ exe
1. من المستودع افتح تبويب **Actions**. إن ظهر زر «I understand my workflows, enable them» اضغطه.
2. اختر **Build FPSystem.exe** من اليسار ← **Run workflow** ← Run workflow (الأخضر).
3. انتظر 5–8 دقائق حتى تظهر علامة ✓ خضراء. (إن ظهرت ✗ حمراء: افتح التشغيلة وانسخ نص الخطأ.)
4. افتح التشغيلة ← أسفل الصفحة قسم **Artifacts** ← اضغط **FPSystem** ← يُنزَّل ZIP، فكّه لتجد `FPSystem.exe`.
للإصدارات الرسمية: أنشئ Release بوسم v1.0 (Releases ← Create a new release ← Tag: v1.0) فيُرفق الـ exe تلقائيًا.

## ثالثًا: تجهيز جهاز البصمة (مرة واحدة)
1. من قائمة الجهاز (Comm / Ethernet) ثبّت **IP ثابتًا** (مثل 192.168.1.201)، المنفذ 4370، ومفتاح الاتصال Comm Key = 0 (أو غيّره في fp_config.json).
2. وصّل الجهاز بكيبل/سويتش على نفس الشبكة (نفس نطاق IP للكمبيوتر، مثل 192.168.1.x).
3. اضبط ساعة الجهاز على الوقت الصحيح.
4. من الكمبيوتر جرّب: افتح CMD واكتب `ping 192.168.1.201` ويجب أن يردّ.
5. أغلق أي برنامج آخر متصل بالجهاز (ZKTime وغيره)، فالجهاز يقبل اتصالًا واحدًا.

## رابعًا: التشغيل والتعريف في النظام
1. انسخ FPSystem.exe إلى الكمبيوتر المتصل بالشبكة (مثلًا C:\FPSystem\) وشغّله بنقرتين. إن ظهر تحذير أزرق: «مزيد من المعلومات ← تشغيل على أي حال».
2. تفتح نافذة النظام مباشرة (المفتاح مضمّن). سجّل الدخول بحسابك.
3. من تبويب **أجهزة البصمة**: أضف الجهاز، الاسم **مطابق تمامًا** (FaceID-1)، IP والمنفذ، الطريقة **«وسيط بايثون»**، وفعّله.
4. من تبويب **ربط البصمات**: اربط (الجهاز + رقم البصمة) بالموظف.
5. اضغط **سحب من الأجهزة** لتجربة فورية. بعدها يسحب تلقائيًا كل 15 دقيقة.
6. لتشغيله مع ويندوز: كليك يمين على أيقونته بجوار الساعة ← «التشغيل مع ويندوز». إغلاق النافذة (X) يُبقيه يعمل في الخلفية؛ للإيقاف الكامل: كليك يمين ← خروج.

## خامسًا: المتابعة وحل المشاكل
مجلد البيانات: اكتب `%LOCALAPPDATA%\FPSystem` في شريط مسار المستكشف:
- `fp_bridge.log` السجل الكامل (أول ما تفتحه عند أي مشكلة).
- `fp_status.json` آخر نجاح/خطأ، `fp_outbox.json` حركات محفوظة تنتظر الإنترنت.
- `fp_config.json` عدّله لتغيير IP احتياطي أو comm_keys أو "interval_minutes" (دقائق السحب)، ثم أعد تشغيل التطبيق.

| المشكلة | الحل |
|---|---|
| «تعذر الاتصال بـ IP» | تحقق من ping، الكيبل، المنفذ 4370، Comm Key، وأن لا برنامج آخر متصل |
| unauthorized | المفتاح لا يطابق showKey الحالي؛ استبدل محتوى `%LOCALAPPDATA%\FPSystem\fp_key.txt` بالمفتاح الصحيح |
| لا تظهر حركات | تأكد من «ربط البصمات»، ومن اسم الجهاز المطابق، ومن ساعة الجهاز |
| لا يوجد إنترنت | تبقى الحركات في fp_outbox.json وتُرسل تلقائيًا عند عودته |
| ويندوز/مضاد فيروسات يحذف الملف | أضف FPSystem.exe للاستثناءات (الملف غير موقّع) |
| النافذة لا تفتح | يُفتح المتصفح تلقائيًا؛ أو ثبّت WebView2 Runtime من مايكروسوفت |
| الجدار الناري يسأل | اسمح بالوصول للشبكة الخاصة |

## سادسًا: التحديث
عدّل الملفات في المستودع (أو ارفع نسخة جديدة من index.html في app/web)، ثم شغّل Build مرة أخرى ونزّل الـ exe الجديد واستبدل القديم. بيانات المستخدم لا تُمسح.

## ملاحظات أمان
- المستودع يجب أن يبقى **Private**، ولا توزّع الـ exe خارج جهة العمل (المفتاح مضمّن).
- لتغيير المفتاح لاحقًا: استبدل app/fp_key.txt وأعد البناء، أو غيّره على الجهاز في `%LOCALAPPDATA%\FPSystem\fp_key.txt`.
